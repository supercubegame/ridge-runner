# T01 严格离线验收

## 用途
复核既有配对采样报告，不调用Lightning、不运行诊断服务、不更改原始JSON。Python3标准库即可，无需Lightning SDK、API凭据或pip安装。运行CI需要GitHub读取固定报告和上传artifact；不能称整个CI完全无网络，只有验收模块无网络调用。

```text
python3 tools/strict_assess.py <报告.json> --output out/strict-assessment.json
python3 tools/strict_assess.py <固定第九轮报告.json> --self-test
```

退出码0为通过，非0为失败或证据不足。--self-test校验原始报告SHA256，避免用伪造样例替代第九轮。不要用python -O运行assert测试。

## 严格口径
探针200并精确匹配随机标记；根路径404且响应长度整数0。拒绝布尔值冒充数值、缺失或重复配对、配对序号跳跃／倒序、缺失退出记录。至少3个连续完整成功对，从首次严格成功对后不能再次失败；服务端分类／TCP／状态计数、自检、退出码及7项保护均需对齐。任何缺项均不算通过。

第九轮结果：严格起点零基pair7，20对成功；21次探针、20次空根404，7次非空根404排除。原报告root_success_count=27仅代表状态码计数，不能作为27次到达服务的证据。原报告不覆盖。

## 边界
这是严格保守的配对报告模型，不适用于任意旧单路径报告或有额外生产访客的服务。计数对齐不是逐请求分布式追踪。短窗口通过不代表长期稳定、自唤醒、自然休眠或计费通过。固定真实报告保证回归输入身份，不使任意输入报告自动可信。
